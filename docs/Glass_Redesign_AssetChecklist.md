# 默认背景美术规格清单

状态：v1（2026-08-19）。配套占位图：`app/src/assets/backgrounds/frost.png`、`app/src/assets/backgrounds/liquid.png`，由 `tools/build_default_backgrounds.py` 生成，纯几何渐变 + 柔化色斑拼出来的抽象底图，不是成品美术，只用来把版式跑起来、把下面这些约束用真实像素验一遍。人类换真图时，本文件是唯一事实来源。

**v1.1（2026-08-19，整合期修订）**：v1 里「安静区」被列为硬约束，前提是主页右下角那撮字裸压在照片上。换皮收口时该前提已被推翻——右下角的信息改坐 `.surface-panel`，字落在 86% 纸色上、底色与照片无关，前端的 `plateMode()` / `scrimShowsOn()` / `.plate-scrim` 三者随之整体删除（见第三节开头）。本次只订正与代码打架的陈述，其余（尺寸格式、整图亮度区间、高频细节）原样有效。

## 一、这张图会被怎么用（先把管线看懂，再谈约束）

背景图现在铺满整个窗口，不再只贴主页一块（见 `PageBackground.tsx` 顶部注释）。图层自下而上：兜底纯色 → 图 → 纸色遮罩（可选，玩家自己调）。

外壳（标题栏、侧栏）与内容容器全部是半透明毛玻璃材质，压在图上方，`backdrop-filter` 各挡不同：

| 材质 | 不透明度（纸色占比） | 模糊半径 | saturate |
|---|---|---|---|
| `.surface-shell`（外壳：标题栏、侧栏） | 72% | 28px | 155% |
| `.surface-panel`（内容容器） | 86% | 20px | 145% |
| `.surface-panel-strong`（信息密集区：长列表、表格、日志台） | 96% | 12px | 130% |
| `.surface-liquid`（侧栏游戏行/主 CTA/Toast/分段控件选中页，仅这四处） | 80% | 14px（frost）/ 10px（liquid，额外 `brightness(1.05)`） | 170%（frost）/ 200%（liquid） |

整张画布现在没有任何一处是裸字：主页右下角那块信息也坐在 `.surface-panel` 上。于是全图只剩一条方向统一的约束——**越清晰（高频细节）越危险**，因为每一寸画面都会被 12–28px 的模糊揉一遍。v1 里那条方向相反的「安静区越清晰越危险」已随裸字一起作废。

内置默认图目前只是静态前端资源（`app/src/assets/backgrounds/`），还没有接入设置页那条「导入即转码即测光」的管线（`crates/aurora-core/src/background.rs`：玩家选的图会被转成 JPEG、压到 1920 宽、同时量出 `PlateZone`）。这条缺口仍然存在：两张 PNG 至今没有任何代码引用，换掉文件不会让任何人看到它们。把它们接成真正生效的内置默认值，需要开发在导入管线或设置页初始化逻辑里补一条内置默认图的加载路径。（前端已不再消费 `PlateZone`，所以这条接线不再需要为默认图补测光；后端是否继续量这个字段是另一个待定问题。）

## 二、尺寸与格式

- 分辨率：**1920×1080**，16:9。这是 `background.rs` 里 `DISPLAY_WIDTH` 常量定的展示宽度上限，超过这个尺寸只是让 WebView 多解码像素，不会更清楚。
- 格式：交付用 **PNG**（无损，换图阶段不需要再引入一次有损压缩误差）。最终玩家自己导入的图会被后端转成 JPEG（quality 88）存档，所以 PNG 只是交付格式，不代表运行时格式——正因为运行时还要过一轮 JPEG，源图更不能指望靠"反正会被压缩所以细节无所谓"这种想法蒙混，压缩只会在细节已经出问题的图上雪上加霜（见第四节）。
- 色彩空间：sRGB。后面所有亮度判据的公式都是按 sRGB 传递函数写的，色彩空间不对，判据全部失真。
- 不需要 alpha 通道（背景图不透明，铺满整个窗口）。

## 三、安静区——已作废，仅存档

**这一节整节不再有约束力。** 它描述的三档渲染分支（`ink` / `paperOn` / `plate`）由 `appearance.ts` 的 `plateMode()` 决定，而该函数连同压暗层已在换皮收口时删除：右下角的字改坐 `.surface-panel`，底色由材质的纸色比例定死，与这块区域的照片亮度再无关系。下面 3.1–3.5 原样保留是为了两件事——一是 `tools/build_default_backgrounds.py` 的自检仍按这套阈值判定（脚本还没跟着改，用它量图时不达标只说明「右下角明暗跨度大」，不再说明「字会读不出来」）；二是万一日后要把裸字做回来，这套推导不必重算。**换真图时不必迁就 3.3 的阈值**，按第四节的整图亮度区间与第五节的高频细节约束设计即可。

### 3.0 原文（存档）

### 3.1 区域定义

右下角，**宽度 = 画布宽 × 28%，高度 = 画布高 × 34%**，右边和下边贴画布边缘。1920×1080 画布上就是像素矩形 `(1382, 713) - (1920, 1080)`。

这块区域装的是主页右下角的信息卡片（版本号/状态一类）。文字怎么渲染，由 `app/src/lib/appearance.ts` 的 `plateMode()` 按这块区域的亮度取样决定：

- **`ink`**：黑墨字直接裸压在图上，不加任何衬底。
- **`paperOn`**：纸色字裸压在图上，底下垫 `brightness(0.5)` 压暗层。
- **`plate`**：以上两档都保不住可读性，退回一块不透明的 `.paper-frost-strong` 纸片——安全，但视觉上就是一块方块贴在图上，不是"字直接印在照片上"的效果，换图如果图图都触发这一档，等于白设计了这块区域。

### 3.2 判据公式（与 `appearance.ts` 逐字对齐）

系统对这块区域取样，记录 10 百分位（最暗一成像素，记 `p10`）与 90 百分位（最亮一成像素，记 `p90`）的 **WCAG 相对亮度**，线性映射到 0..255 存储。取两端而不是均值，是因为文字读不读得出取决于最不利的那一个像素，不是平均水平。

```
L_INK      = 0.007971   （墨字的等效相对亮度）
L_PAPER_ON = 0.905855   （纸色字的等效相对亮度）
PAPER_SRGB = 242        （--color-paper 的等效灰阶，用于纸色遮罩合成）
SCRIM_BRIGHTNESS = 0.5  （压暗层系数，与 app.css 的 .plate-scrim 必须是同一个数）
NAKED_TARGET = 5.5      （裸字要求的对比度，比 WCAG AA 的 4.5 高一档）
```

墨字档判据（不叠压暗层，`dim = 1`）：

```
darkEnd = effectiveLuma(p10, veil=0, dim=1)
(darkEnd + 0.05) / (L_INK + 0.05) >= 5.5
```

纸色字档判据（叠 `brightness(0.5)` 压暗层）：

```
brightEnd = effectiveLuma(p90, veil=0, dim=0.5)
(L_PAPER_ON + 0.05) / (brightEnd + 0.05) >= 5.5
```

两档判据都不过，落 `plate`。以上按玩家还没手动加纸色遮罩（`veil = 0`，全新安装的默认状态）计算——玩家在设置页把遮罩拉高，会把这块区域的合成亮度往 `PAPER_SRGB`（242，很亮）方向拉，即墨字档更容易过、纸色字档更难过，属于玩家自己的选择，本清单按默认状态给硬约束。

### 3.3 换算成可以直接测的数字

把上面的公式解出来（`tools/build_default_backgrounds.py` 里 `luma_of`/`srgb_of` 精确复算过，不是手推估算）：

| 判据 | 需要满足（0..255 尺度，`p10`/`p90` 原始值） | 相对亮度 |
|---|---|---|
| 过 `ink`（黑墨字，corner 要够亮） | `p10 >= 69` | 相对亮度 >= 27.1% |
| 过 `paperOn`（纸色字，corner 要够暗） | `p90 <= 142` | 相对亮度 <= 55.7% |

硬阈值不能贴着卡：不同取样实现（最近秩 vs 插值百分位数）在边界像素上会有一两个点的出入，压缩/重采样也会引入误差。**设计目标留够余量**：

- 选纸色字档（推荐，见 3.4）：目标 `p90 <= 115`（比硬阈值多留 27 点）。
- 选墨字档：目标 `p10 >= 100`（比硬阈值多留 31 点）。
- 无论选哪档，`p90 - p10 <= 45`（0..255 尺度，约等于相对亮度全距离 17.6 个百分点）——这一条防的是"均值看着很稳，但一小撮高光或阴影单独把某一端顶穿阈值"，纯看平均亮度看不出这个问题，必须看两端的极差。

### 3.4 该往哪个方向设计

两档二选一，不要设计成"卡在中间、指望蒙对"：

- **纸色字档（推荐）**：把安静区设计成一块相对均匀的暗调（深色照片角落、阴影、深色物体都行），让 `p90` 稳稳压在 115 以下。多数摄影构图里角落本来就容易有自然阴影，顺势设计比硬凑亮角落更自然。
- **墨字档**：把安静区设计成一块相对均匀的亮调（天空、浅色墙面、留白），让 `p10` 稳稳过 100。

不管选哪个方向，**安静区内部不能有孤立的强反差细节**——一小片高光（灯泡、反光、白色物体边缘）如果落在这 28%×34% 的取样窗口里且面积超过窗口像素数的 10%，就会把 `p90` 单独顶穿纸色字档的阈值；反过来一小片深黑阴影也能顶穿墨字档的 `p10` 阈值。这块区域要读起来"安静"，不是审美偏好，是量出来会改变渲染分支的硬指标。

### 3.5 怎么量（可执行，不是纸上谈兵）

用 `tools/build_default_backgrounds.py` 自带的测量模式，不用另外写脚本：

```
python tools/build_default_backgrounds.py --measure <候选图片路径>
```

会打印安静区矩形、`p10`/`p90`/极差、两档对比度、最终判定分支（`ink` / `paperOn` / `plate`）、是否落在 3.3 节的设计余量内。不落在余量内会以非零退出码结束——接入 CI 或者提交前跑一遍都行。

这套测量是**近似判据**：后端 Rust 侧实际用什么百分位数插值方法，不在本次任务的文件范围内（未读 `background.rs` 里取样那部分实现），量图时靠上面留的设计余量去覆盖这类小出入，不是去追求和后端小数点后完全对齐。真正的准出条件是图片接入内置默认值管线后，`appearance.ts` 拿到的真实 `PlateZone` 落在 `ink` 或 `paperOn`，而不是这个脚本的输出本身。

## 四、整图亮度区间建议

不是硬约束（没有对应的运行时分支会因此报错），但直接影响毛玻璃效果看不看得出来，建议当作准出前的目视+抽测项。

外壳材质（标题栏、侧栏）常年铺在图上方，纸色占比只有 72%——是所有材质里最透的一档，也就是背景亮度对它观感影响最大的一档。按 CSS 的 `color-mix(in srgb, ...)` 是在 sRGB 空间直接线性混合（与 `appearance.ts` 的 `composite()` 同一套口径），可以反推：

```
panel_srgb(bg) = 0.72 × 242 + 0.28 × bg = 174.24 + 0.28 × bg
```

- **背景太亮（bg 接近 242）**：`panel_srgb` 也逼近 242，玻璃与纯色纸片的差值小于约 15 sRGB 时，肉眼基本分不出"这里透着一张图"和"这里就是不透明纸"——毛玻璃的存在感消失，等于白做了这层材质。反推：`bg <= 188` 时差值才能稳定摸到 15 以上。
- **背景太暗（bg 接近 0）**：`panel_srgb` 被拉向 174 附近，读出来是一块暖灰，不再像"纸"（`--color-paper` 是 #f3f2f0，接近纯白）。要保住"看起来是纸不是灰"（与 242 的差值不超过约 40 sRGB），反推：`bg >= 99`。

综合建议：**外壳所在的左侧栏、顶部标题栏这两条常驻玻璃地带，背景亮度控制在 sRGB 灰阶 100–190 区间**（约相对亮度 15%–53%），避免大片近纯白或近纯黑。这条只约束"常年被玻璃盖住的区域"，画面中段、右下角安静区不受这条限制——安静区有自己独立的、更严格的判据（第三节），两者冲突时以第三节为准（安静区允许比 100 更暗，只要过 `paperOn` 的阈值）。

## 五、为什么不能用高频细节多的照片

两个独立的理由，任何一个单独成立就足以否掉一张候选图：

1. **模糊会把细节变成噪点，不是变成柔和**。上表列的模糊半径从 12px 到 28px 不等，`backdrop-filter: blur()` 对高频细节（树叶、碎石、砖缝、织物纹理这类像素级明暗剧烈跳变的内容）的处理不是"变模糊的照片"，是把大量微小的明暗跳变揉成一团彩色噪声——外壳那档还叠了 130%–200% 的 `saturate()`，噪声的颜色偏差会被放大，实拍出来是脏兮兮的一片，而不是干净的磨砂质感。`app.css` 里否掉标题栏渐隐方案的原因写得很直白：实拍是"一条发灰的脏带子"，同一个坑，高频照片会在四种材质上都踩一遍，不是踩一次。
2. **高频细节会让安静区的百分位数不稳定**。第三节的 `p10`/`p90` 判据本质上是在赌"这块 28%×34% 的窗口里像素亮度足够集中"。一张布满细碎明暗变化的照片（比如落满光斑的树荫、反光的水面），哪怕平均亮度完全落在建议区间，10%/90% 分位数也可能被少数几撮极亮/极暗像素单独顶到阈值外——第三节已经把这条量化成了 `p90 - p10 <= 45` 的极差上限，这里只是说明背后的因果：高频细节是极差失控的最常见来源。

选图方向：优先浅景深/柔焦摄影、天空/水面/雾气一类本身低频的场景、大色块插画，或者干脆是渐变+简单几何构成（本次占位图走的就是这条路）。要用实拍照片，构图上让主体细节避开右下角安静区，且全图避免大面积高对比纹理。

## 六、占位图现状

`tools/build_default_backgrounds.py` 生成的两张图都是纯程序化构成：竖向双色渐变 + 两枚高斯模糊柔光斑 + 一道斜向柔光带 + 右下角一块专门压平的柔化色块（保证安静区判据）。没有任何照片、没有 AI 生图、没有素材库内容，色相上 frost 偏冷（冰蓝→石板蓝灰）呼应"毛玻璃"字面意思，liquid 偏暖（暖米→深青）呼应"液态玻璃"的金属光泽意象，两者用同一套安静区/整体亮度约束，跑同一个脚本的自测都在设计余量内（`p90` 分别为 22.5 与 15.2，硬阈值是 142，余量非常宽——留这么大余量是因为占位图本来就该在这条约束上做到绝对不出错，把余量花在别处）。

人类换真图时，`tools/build_default_backgrounds.py` 的 `build_frost()`/`build_liquid()` 两个函数不需要保留或参考——它们只是占位图的生成逻辑；`measure_quiet_zone()`/`--measure` 这条测量路径才是要长期留着复用的部分。
